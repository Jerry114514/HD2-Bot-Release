# AstrBot 插件市场上架 · 合规整改说明（2026-11）

针对 AstrBot Cloud 插件市场审核结论中的两项不合规问题，本仓库已完成修改，并顺带处理了评审建议。
本文逐条对应审核意见，给出**当前代码位置**与**验证方式**，提交复审时可直接引用。

> 审核结论：未发现恶意行为；需整改「日志记录」与「持久化位置」两项。

## 一、整改概览

| 审核意见 | 结论 | 本次变化 |
| --- | --- | --- |
| 1. 日志必须且只能从 `astrbot.api` 导入 | 已修复 | 删除全部 `import logging`；统一 `from astrbot.api import logger` |
| 2. 缓存/状态/日志写入插件安装目录 | 已修复 | 新增 `paths.py`，全部运行期写入落到 `data/plugin_data/<plugin_name>/` |
| 3. `_translate_objective_desc` 死代码直连外部 API、读取本机凭据 | 已删除 | 翻译统一交给框架 LLM（`llm_generate`） |
| 4. `scripts/` 等部署辅助工具建议从安装包精简 | 已处理 | `.gitattributes export-ignore`，市场 zip 不再包含 |

## 二、日志规范整改

审核指出的两处违规现已全部消除：

| 原违规位置 | 现状 |
| --- | --- |
| `plugins/astrbot_plugin_hd2_common/diagnostics.py:3,61`（`import logging` / `logging.getLogger(__name__)`） | `diagnostics.py:17-32` 改为 `from astrbot.api import logger`；无任何 `logging` 引用 |
| `plugins/astrbot_plugin_hd2_wiki/wiki_data.py:9,18,392`（`import logging` / `logging.getLogger(__name__)`） | `wiki_data.py:20-35` 改为 `from astrbot.api import logger`；`:392` 附近的调用不变，用的已是框架 logger |

另核查了 12 个插件的全部源文件，其余模块本就使用 `from astrbot.api import logger`，不存在其它 `logging` 用法。

关于离线工具/单元测试：`diagnostics.py` 与 `wiki_data.py` 需要被 `scripts/` 下的离线工具在**无 AstrBot 环境**中导入，

（`_StderrLogger`，不引入 Python 内置 `logging`）。在 AstrBot 运行时该分支不会生效，实际始终使用框架 logger。

新增回归测试：`tests/test_market_compliance.py::LoggingComplianceTests::test_plugins_never_use_stdlib_logging`
对 `plugins/**/*.py` 做 AST 扫描，出现 `import logging`、`from logging import ...` 或 `logging.xxx` 即失败。

## 三、持久化位置整改

新增 `plugins/astrbot_plugin_hd2_common/paths.py`（公共模块，12 个插件共用），统一解析插件数据目录：

1. 环境变量 `HD2_PLUGIN_DATA_DIR`（离线工具/测试可显式指定）；
2. AstrBot 官方接口 `StarTools.get_data_dir(plugin_name)`（即 `data/plugin_data/<plugin_name>`）；
3. 无框架时按源码布局推导（`<AstrBot>/data/plugins/<plugin>/…` → `<AstrBot>/data/plugin_data`；
   仓库开发布局 → `<repo>/data/plugin_data`）。

对外接口：`plugin_data_dir(name, *parts)`、`plugin_cache_dir(name, *parts)`、`plugin_log_dir(name)`，按需 `mkdir`。

逐条对照审核意见：

| 原写入位置 | 现状 |
| --- | --- |
| `plugins/astrbot_plugin_hd2_common/data.py:40` `CACHE = <插件目录>/cache` | `data.py:42` `CACHE = plugin_cache_dir("astrbot_plugin_hd2_common")` |
| `plugins/astrbot_plugin_hd2_war_report/main.py:69,72` `api_watch_state.json`、`mo_seen.json` | `main.py:70-73` 统一写到 `plugin_data_dir("astrbot_plugin_hd2_war_report", "state")` |
| `plugins/astrbot_plugin_hd2_wiki/wiki_data.py:19` `CACHE_DIR` | `wiki_data.py:38` `str(plugin_cache_dir("astrbot_plugin_hd2_wiki"))` |
| `plugins/astrbot_plugin_hd2_common/diagnostics.py:11` 指令日志 `temp/指令日志.jsonl` | `diagnostics.py:34` 写到 `data/plugin_data/astrbot_plugin_hd2_common/logs/commands.jsonl` |

同时把同类写入一并迁移（避免复审判定「只改点名处」）：

| `plugins/astrbot_plugin_hd2_war_report/report_card.py:32` | `data/plugin_data/astrbot_plugin_hd2_war_report/cache/`（banners、biomes、planet_icons、effect_id_cn、成品卡） |

运行期目录结构示例：

```

├── astrbot_plugin_hd2_common/
│   ├── cache/site_<hash>.json      # 主站快照缓存
```

**兼容说明**：旧版本写在 `plugins/<name>/cache` 与仓库根 `temp/` 下的文件不再读取，也不会被迁移——
这些内容全部是可再生数据（站点快照、缩略图、成品卡图、MO 去重记录、`/api` 基线），缺失时会自动重新抓取/重建。
插件安装目录保持只读，符合「安装目录随市场更新整体替换」的预期。

离线 WebUI（`scripts/hd2_webui.py`）已同步改为读取 `diagnostics.LOG_FILE`，并保留旧路径 `temp/指令日志.jsonl` 作为
开发期历史日志的回退读取（只读，不写入）。

新增回归测试：`tests/test_market_compliance.py::PersistenceComplianceTests`
（禁止 `__file__` + `"cache"` 形式的写入路径、校验 `.gitignore` 已忽略 `data/plugin_data/`），
以及 `tests/test_plugin_paths.py`（8 项：环境变量优先、`StarTools` 优先、仓库布局回退、运行期常量不得指向插件安装目录等）。

## 七、第二轮整改（2026-11-08）：不再改写系统提示词

第二轮自动安全检查指出：`plugins/astrbot_plugin_hd2_wiki/main.py` 的 `on_llm_request` 钩子在每次普通聊天中
把回复长度策略与 `[HD2_WIKI_REFERENCE]` 资料块追加到 `req.system_prompt`，既改写了系统提示词，又破坏上游提示词缓存命中率。

| 项目 | 整改前 | 整改后 |
| --- | --- | --- |
| 回复长度策略 | `req.system_prompt = ...` 追加（原 `main.py:81-84`） | `_append_temp_context(req, render_reply_policy(...))` |
| Wiki 资料块 | `req.system_prompt = ... + reference`（原 `main.py:105`） | `_append_temp_context(req, reference)` |
| 异常降级块 | `req.system_prompt = ...`（原 `main.py:119`） | `_append_temp_context(req, render_chat_reference(fallback))` |

实现要点：

- 新增 `_temp_text_part()`：优先使用框架 `TextPart(text=...).mark_as_temp()`（AstrBot 4.27–4.29 的实际 API；
  评审材料中的 `make_as_temp` 为同一语义，代码同时兼容两种写法），无框架环境退化为本地等效内容块。
- 新增 `_append_temp_context()`：只向 `req.extra_user_content_parts` 追加，系统提示词保持原样。
- 临时块带 `_no_save` 标记：框架发给模型后不会写入会话历史，也不污染下一轮的缓存前缀。
- 检索范围、超时预算、异常降级行为保持不变；`hd2_wiki_lookup` 工具仍作为可选的按需检索通道。

验证：`tests/test_chat_grounding.py` 断言 `system_prompt` 一字未改、临时块含长度策略与资料块且带 `_no_save`、
重复调用不重复注入；`tests/test_market_compliance.py::PromptComplianceTests` 用 AST 守卫禁止插件给
`system_prompt` 赋值。全量 `scripts/check.py` 174 项测试，仅剩本机缺少 `beautifulsoup4`/`markdown` 导致的
`test_search` 既有失败（CI 安装 `requirements-wiki.txt` 后为绿）。

## 合并后的指令无响应回归（2026-10-31）

旧事件替身直接给处理器传入 `/roll`，SDK 检查也只做导入，未覆盖 AstrBot 先删除唤醒前缀的真实流程。实际 WakingCheckStage → StarRequestSubStage → RespondStage 离线复现：原代码收到 `/roll` 后得到 `roll`，守卫停止事件，发送捕获为空。

此外，旧配置的 `bot.groups` 是 NapCat 群号，缺省 `bot.platform=napcat`；原守卫不区分通道，将数字名单应用到官方 QQ 的群 OpenID，同样停止有效指令。这与用户提供的通道日志及配置形态相符；没有取得其完整生产日志或操作远端实例。

修复统一通过 `commands.parse_event` 读取消息对象保留的原始文本，覆盖守卫、监控、战报、抽取、Wiki、星球、变种和帮助；群名单只用于所配置通道，明确配置的官方名单及 NapCat 名单继续执行。没有放宽普通聊天为无斜杠指令，也没有移除 AstrBot 自身的白名单。

回归入口为 `tests/test_event_commands.py` 与 `scripts/sdk_pipeline.py`。后者使用真实 AstrBot 4.29.3 的上述三个阶段、已注册处理器和事件结果类型，覆盖前缀剥离、@/非@、私聊、普通消息、未知指令、文本回退和两种群标识；只有会话存储、业务数据/绘图及发送端隔离。`qq_official`/`qq_official_webhook`/`aiocqhttp` 在此是事件的平台元数据，未运行真实平台适配器或发送消息。生产收发仍需部署后复测。

## 全插件框架复核（2026-10-31，接续上述回归）

新增并复现的缺陷：

| 问题 | 修复与回归证据 |
| --- | --- |
| OneBot 进群通知被 commands-only 守卫拦截，欢迎处理器未运行 | 守卫区分真实 OneBot notice；用 SDK notice 转换器产生事件，检查欢迎一次、重复/自身/离群/禁用/不在白名单时不发 |
| `/help` 在内置帮助和 HD2 帮助中各发一次 | HD2 帮助优先级低于守卫、高于内置处理器；同时加载内置帮助验证单次回复 |
| 明确文字或渲染回退又被全局 T2I 转成图片，官方纯文本默认走 Markdown | 共用 `text_reply` 显式关闭 T2I 与 Markdown；真实修饰阶段和官方发送载荷验证 |
| 跨 `yield` 保存 ContextVar token，生成器被框架从另一任务关闭时报错并泄漏请求ID | `request_scope` 只在每次推进/关闭期间设置与复位；测试工作线程取消及跨任务关闭，无迟到回复或上下文泄漏 |
| 按 `data.plugins` 加载时，跨插件导入 common/monitor 的 `main.py` 再注册一套入口 | 数据源助手移至无插件注册的 `sources.py`，旧 common 入口保留公开助手导出；日志直接复用 diagnostics。真实命名空间下检查不存在顶层重复入口 |

当前 SDK 回归扩为 WakingCheckStage → WhitelistCheckStage → ProcessStage → ResultDecorateStage → RespondStage，开启默认 LLM 路由但用记录器替代模型，确认 HD2 指令、错误、通知均不意外进入模型。显式 `/分析` 校验真实 SDK 方法签名，仍使用固定模型回复；全部十个插件均纳入注册。

QQ 官方与 OneBot 的群聊/私聊、文本/图片测试调用真实适配器 `send`，检查 OpenID/数字ID、消息ID、媒体上传类型和图片字节；只在 HTTP/OneBot API 边界用内存桩截断。失败用例验证不会重新抽取或被当作成功发送。战报/Wiki/星球/帮助的图片路径及分页、其余指令正常参数与错误提示另经框架发送阶段验证。

边界：未启动平台连接、登录账号或发送真实消息；未测试其他 AstrBot 版本。该 SDK 的修饰钩子仅调用 `stop_event()` 时仍可能进入回复阶段，HD2 未注册这种钩子；中止发送的测试使用清空结果再停止，未修改第三方 SDK。发送端自身的重试策略由 SDK 管理，真实服务权限和回执仍待部署验收。

# 第二轮市场合规整改章程

> 状态：代码与自测完成，待提交复审。对象：`plugins/astrbot_plugin_hd2_wiki`。
> 触发：AstrBot Cloud 自动安全检查第二轮未通过（系统提示词被逐轮改写）。

## 一、评审意见

`plugins/astrbot_plugin_hd2_wiki/main.py` 的 `on_llm_request` 钩子（原约 63–121 行）在每次普通聊天请求中，把随用户消息与检索结果动态变化的内容持续追加到 `req.system_prompt`：

1. 回复长度策略（`render_reply_policy`）；
2. `[HD2_WIKI_REFERENCE]` Wiki 资料块（`render_chat_reference`，含检索到的正文）。

后果是系统提示词每轮都被改写，既篡改了系统上下文，又破坏上游提示词缓存命中率。评审要求改为 `req.extra_user_content_parts`（临时内容，需标记）或仅通过 `hd2_wiki_lookup` 工具注入。

## 二、整改原则

1. **系统提示词只读**：插件内不得对 `req.system_prompt` 赋值；需要补充上下文时只能追加一次性内容块。
2. **一次性上下文走 `extra_user_content_parts`**：使用框架 `TextPart` 并以 `mark_as_temp()` 标记（AstrBot 4.27+ 的实际方法名；评审材料里的 `make_as_temp` 视为同一语义，代码同时兼容两种写法）。
3. **不落库**：临时块由框架 `_no_save` 机制过滤，不写入会话历史，也不影响下一轮缓存前缀。
4. **行为等价**：检索判定、时限预算、异常降级保持原样；检索失败时仍注入 `status: unavailable` 的"档案无法确认"数据块。
5. **版本兼容**：兼容 AstrBot 4.27–4.29；离线脚本/单测无框架时使用本地等效内容块，不引入新依赖。
6. **单一职责**：只改注入通道，不动 Wiki 渲染、检索逻辑、卡片缓存与其它插件。

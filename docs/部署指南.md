## 1. 架构与两种接入方式

```
QQ 群 / 私聊
   │
   ├─(A) 官方 QQ 机器人（腾讯开放平台 API）
   │        └── AstrBot 适配器 qq_official / qq_official_webhook
   │
   └─(B) SnowLuma（OneBot v11，注入 QQNT 客户端）
            └── AstrBot 适配器 aiocqhttp（反向 WebSocket）
                        │
                        ▼
              AstrBot ≥ 4.29.3（事件分发 / 唤醒 / 白名单 / LLM）
                        │
                        ▼
   HD2 套件：12 个子系统（战报、战线、DSS、战役、星球、Wiki、Roll、
   BTK、拆毁值、查表、变种、欢迎）+ guard 守卫 + /api 监测
        ├── 主站快照 data.json（战况、星球、战役）
        ├── 中文 Wiki helldivers.wiki.gg/zh（事实检索）
        └── AstrBot LLM Provider（/分析 与普通聊天，可选）
```

两条通道可以同时存在（两个 AstrBot 适配器并行），项目用 `bot.platform` + `bot.platform_id` 决定插件听谁的话。

| 维度 | 官方 QQ 机器人（qq_official） | SnowLuma（OneBot v11，aiocqhttp） |
| --- | --- | --- |
| 登录方式 | 腾讯开放平台 appid/secret，机器人由群主/管理员添加进群 | QQNT 客户端扫码登录机器人号 |
| 需要桌面 QQ | 否 | 是（SnowLuma 注入 QQ 进程，Windows 桌面 / Linux Docker + noVNC） |
| 群号形式 | **群 OpenID**（32 位十六进制，每机器人每群唯一） | **数字群号**（如 `134324143`） |
| 指令回复、图片 | 支持，受平台权限与图片上传接口约束 | 支持 |
| 主动群推送（控制台） | 不支持 | 支持（OneBot HTTP，默认 3000） |
| 进群欢迎 | 不支持（收不到成员变动通知） | 支持 |
| 引用候选菜单 | 支持，菜单标题带 `〔菜单 XXXXXXXX〕` 短标记 | 支持，按发送回执绑定 |
| 唤醒 | 群里默认必须 @机器人 | @ 或私聊 |
| 官方限制 | 主动消息配额小、群消息需权限审批、Markdown/富媒体按平台能力 | 取决于 QQ 号本身，容易被风控 |

> ⚠️ 不要同时安装「市场整包」和「12 个分散插件目录」，否则同一批指令会注册两遍（重复回复）。切换部署方式前先卸载另一套。

## 2. 前置条件

| 组件 | Windows | Linux | 说明 |
| --- | --- | --- | --- |
| 操作系统 | Windows 10/11 x64 | x86_64 / arm64 主流发行版 | SnowLuma 官方包以 x64 为主 |
| AstrBot | **≥ 4.29.3**，推荐 4.29.4 桌面版 | ≥ 4.29.3，Docker / pip / 源码 | 低于 4.29.3 市场整包会被版本闸门拦截，`/roll` 行为也不同 |
| Python | 3.11+（推荐 3.12） | 3.11+ | 跑控制台/同步脚本；AstrBot 自带 Python 也可用 |
| Node.js | ≥ 22 | ≥ 22 | `/roll` 黑箱抽取走 `draw_bridge.mjs`，缺少会提示「抽取暂不可用」 |
| Pillow / bs4 / RapidFuzz | 见 `requirements.txt` | 同左 | 画图卡、Wiki 表格、名称纠错 |
| 中文字体 | 系统自带雅黑即可 | 必须装 CJK 字体 | Linux 见 §9.1 |
| QQ 客户端 | QQNT 9.9.x | Docker 镜像内含 | 仅 SnowLuma 通道需要 |
| 网络 | 可访问 GitHub、主站、wiki.gg | 同左 | 国内网络可能需要镜像/代理 |
| LLM Provider | 可选 | 可选 | 只有 `/分析` 与普通聊天需要 |

磁盘预留：AstrBot 约 0.5–1 GB，SnowLuma + QQ 约 0.5 GB，插件与缓存 < 50 MB。

> **关于版本闸门**：`astrbot_version: ">=4.29.3"` 写在**仓库根** `metadata.yaml`，只有「市场整包」会读它并在加载时拦截。用分散部署（路线 B）把 12 个插件目录直接放进 `data/plugins/` 不会触发闸门，但 4.29.2 及更早仍有已知差异：`/roll` 抽取结果与 4.29.3+ 不一致、官方 QQ 引用菜单可能持续提示「无法确认」、依赖 4.29.3 新接口的调用可能报错。**仍建议升级到 4.29.3+**（当前验证版本 4.29.4）。

## 3. 部署路线怎么选

| 场景 | 建议 |
| --- | --- |
| 只想让机器人在群里跑起来，不折腾控制台 | **路线 A（市场安装）** |
| 需要一键启动、Web 控制台、群发推送、WS 注入测试 | **路线 B（仓库部署）** |
| 要接官方 QQ 机器人 | 路线 A 或 B 均可，按 §7 配置 |
| 要接 SnowLuma（最完整能力） | 路线 B 更顺（一键启动会拉起 SnowLuma） |
| Linux 服务器（无桌面） | 路线 B + §9 Docker 方案 |

## 4. 路线 A：插件市场安装

1. 打开 AstrBot WebUI（默认 `http://127.0.0.1:6185`）。
2. 插件市场 → 搜索 **`HD2 战况机器人`** 或 `astrbot_plugin_hd2_suite` → 安装。
   - 若提示版本不兼容：先升级 AstrBot 到 ≥ 4.29.3（弹窗里的「无视警告，继续安装」过不了加载闸门）。
3. 安装目录（Windows）：

   ```
   C:\Users\<你>\.astrbot\data\plugins\HD2-Bot-Release\
   ├── main.py                 # 单一注册入口（12 子系统委托）
   ├── metadata.yaml           # 市场条目：版本、astrbot_version 闸门
   ├── config.example.json
   ├── hd2_config.py           # 配置加载器
   ├── persona\                # 人格文本
   ├── tables\                 # 对照表、图标数据
   └── plugins\astrbot_plugin_hd2_*\   # 12 个子系统实现
   ```

4. 复制 `config.example.json` 为同目录 `config.json`，按 §6 填写（至少 `bot.self_id`、`bot.groups`、`bot.platform`）。
5. 按 §7（官方 QQ）或 §8（SnowLuma）接入平台；`/分析` 需要 §10 配置 Provider。
6. 重载插件（或重启 AstrBot），群里发 `/帮助` 验证。

> 市场包按 `.gitattributes` 的 `export-ignore` 发布，**不含** `scripts/`、`tests/`、`docs/`、`sync_plugins.py`、`start.bat`。也就是说：市场装机只有插件运行时；要用一键启动、Web 控制台、群发推送、`ws_inject` 测试，请另外克隆仓库（路线 B），指向同一个 AstrBot 实例即可。
>
> 套件模式下 `main.py` 会把插件目录加入 `sys.path`，`config.json` 与 `tables/` 会从插件目录解析，不必设置 `HD2_PROJECT_DIR`；但若你希望控制台/脚本也读同一份配置，见 §6.8。

### 从分散部署迁移到市场包

```powershell
# 1) 停掉 AstrBot（或至少卸载 HD2 插件）
# 2) 备份并移走旧的 12 个插件目录（不要直接删）
$dst = "$env:USERPROFILE\.astrbot\data\plugins"
$bak = "$env:USERPROFILE\.astrbot\data\plugins\.hd2-backup-" + (Get-Date -Format "yyyyMMdd-HHmmss")
New-Item -ItemType Directory -Path $bak -Force | Out-Null
Move-Item "$dst\astrbot_plugin_hd2_*" $bak
# 3) 市场安装 HD2-Bot-Release，复制 config.json
# 4) 重启 AstrBot，/帮助 验证
```

## 5. 路线 B：仓库克隆 + 分散部署

### 5.1 克隆与配置

```powershell
git clone https://github.com/Jerry114514/HD2-Bot-Release.git C:\HD2-Bot
cd C:\HD2-Bot
copy config.example.json config.json
# 用编辑器填写 config.json（见 §6）
```

```bash
git clone https://github.com/Jerry114514/HD2-Bot-Release.git ~/HD2-Bot
cd ~/HD2-Bot
cp config.example.json config.json
```

### 5.2 安装依赖

```powershell
python -m pip install -r requirements.txt
python -m pip install -r requirements-wiki.txt      # Wiki 表格 / 名称纠错
python -m pip install -r requirements-browser.txt   # 可选：浏览器兜底、WS 注入
python -m playwright install chromium               # 仅装了 browser 依赖时
```

### 5.3 设置 HD2_PROJECT_DIR（分散部署必做）

插件通过环境变量定位项目根，用于 `import hd2_config`、读取 `config.json` 与 `tables/`。**不设置时插件会退回内置默认值：没有群白名单、没有 SnowLuma token、读不到对照表。**

```powershell
# 永久（新开的程序/服务才能继承，需重启 AstrBot）
setx HD2_PROJECT_DIR "C:\HD2-Bot"
# 当前会话临时生效
$env:HD2_PROJECT_DIR = "C:\HD2-Bot"
```

```bash
# Linux：写进启动环境（systemd 用 Environment=，shell 用 export）
export HD2_PROJECT_DIR="$HOME/HD2-Bot"
```

> 关键：AstrBot 进程必须继承这个变量。Windows 下 `setx` 后要完全退出并重启 AstrBot；用 IDE/脚本启动 AstrBot 时要在同一会话里设置。

### 5.4 同步插件到 AstrBot

```powershell
$target = "$env:USERPROFILE\.astrbot\data\plugins"
python sync_plugins.py --target $target --dry-run   # 预览将写入哪些文件
python sync_plugins.py --target $target             # 首次部署
python sync_plugins.py --target $target --update    # 更新：覆盖已有不同文件
```

- 只同步 `plugins/astrbot_plugin_hd2_*`，不会复制缓存、不会覆盖已有的 `welcome_config.json`、不会删除其他插件。
- 覆盖前旧文件备份到 `<target>\.hd2-sync-backups\<uuid>\`。
- 更新完成后**重载全部 12 个插件**（或重启 AstrBot）；运行中混用新旧核心会出现难以排查的 `ImportError` / 行为不一致。

验证：

```powershell
Get-ChildItem "$env:USERPROFILE\.astrbot\data\plugins" -Directory -Filter "astrbot_plugin_hd2_*" |
  Select-Object -ExpandProperty Name
# 期望 12 个：btk common demolition guard lookup monitor planet_info roll
#            variant_query war_report welcome wiki
```

日志 `C:\Users\<你>\.astrbot\logs\backend.log` 中出现 12 条 `Loading plugin astrbot_plugin_hd2_*` 即加载成功。

## 6. 项目配置 config.json

### 6.1 加载顺序与热读

优先级：`HD2_CONFIG` 环境变量指定的文件 → `<项目根>/config.json` → `hd2_config.py` 内置默认值。

- 改完 `config.json` **不需要重启 AstrBot**：加载器按文件签名（路径 + mtime + 大小）缓存，下次读取自动生效。
- 例外：`bot.platform` 影响守卫/欢迎/启动器的分支判断，改完建议重载插件。
- `config.json` 含账号与 token，**不要提交**（`.gitignore` 已排除）。

### 6.2 `bot` 段

| 键 | 必填 | 说明 |
| --- | --- | --- |
| `platform` | 建议 | `snowluma`（等价 `napcat` / `onebot`，运行时归一化为 OneBot 通道）或 `qq_official`。决定守卫群名单对哪条通道生效 |
| `platform_id` | 可选 | AstrBot 中该平台适配器的**确切 ID**（如 `HD2_QQbot`、`hd2_bot_private`）。填了则只处理该适配器事件；留空不按适配器过滤 |
| `self_id` | 建议 | 机器人账号标识。OneBot 填 QQ 号；官方 QQ 通道不依赖它，可留空 |
| `admin_qq` | 可选 | 管理员 QQ，部分提示/权限预留 |
| `groups` | 强烈建议 | 本通道的群名单：OneBot 填**数字群号**，官方 QQ 填**群 OpenID**（字符串），两者不能混用 |
| `default_group` | 可选 | 控制台推送默认目标群（仅 OneBot 通道有效） |
| `allow_chat` | 可选 | `true` 时非指令消息交给 AstrBot LLM（启用 Wiki 事实层）；默认 `false`，只响应指令 |

> `groups` 为空数组 = 插件不做群限制（AstrBot 自身白名单仍然生效）。

### 6.3 `snowluma` 段（仅 OneBot 通道）

| 键 | 说明 | 默认 |
| --- | --- | --- |
| `webui_url` | SnowLuma WebUI 地址 | `http://127.0.0.1:5099` |
| `onebot_http` | OneBot v11 HTTP 服务（控制台群发走它） | `http://127.0.0.1:3000` |
| `access_token` | SnowLuma 生成的 OneBot accessToken | 空 |
| `dir` | SnowLuma 解压目录（含 `launcher.bat` / `launcher.sh` / `index.mjs`） | 空 |
| `qq_exe` | QQNT 可执行文件，一键启动会顺手拉起 | 默认 QQNT 路径 |
| `ws_url` | 反向 WS 地址（指向 AstrBot） | `ws://127.0.0.1:6199/ws` |

### 6.4 `astrbot` 段

| 键 | 说明 |
| --- | --- |
| `exe` | AstrBot 启动器路径。Windows 桌面版是 `astrbot-desktop-tauri.exe`；Linux 可指向 wrapper 脚本，Docker 部署留空（端口已由容器映射） |
| `python` | 解释器路径（AstrBot 自带或系统 Python）。控制台、子进程、看门狗都用它 |
| `app_dir` | AstrBot 应用目录（`backend\app`），部分诊断读取用 |
| `webui_port` | AstrBot Dashboard 端口，默认 `6185` |
| `ws_port` | 反向 WS 端口，默认 `6199` |
| `data_dir` | AstrBot 数据目录；留空自动探测（`~/.astrbot/data`、项目同级 `data/` 等）。多实例共存时**必须显式指定** |
| `dashboard_user` / `dashboard_password` | AstrBot 登录凭据。填了才能用控制台的「零重启热重载」；仍是默认密码时 AstrBot 拒绝登录，控制台会降级为重启 |

### 6.5 `chat` 段

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `wiki_grounding` | `true` | 游戏知识问题在 LLM 请求前注入 Wiki 证据 |
| `wiki_timeout_seconds` | `5.5` | 检索总预算；超时只要求模型说明「档案未核实」，不阻断回复 |
| `wiki_context_chars` | `2600` | 注入正文字符上限 |
| `max_reply_chars` | `180` | 普通聊天长度预算（只指导模型，不截断） |

### 6.6 `data` 段

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `site_base` | `https://jerry114514.github.io/HD2-Galatic_war-Map` | 主站基址 |
| `news_json_url` | 同上 + `/data.json` | 快照入口；可换镜像 |
| `news_cache_ttl` | `120` | 内存缓存秒数 |
| `campaign_zh_cache_ttl` | `300` | 战役中文缓存 |
| `official_texts_cache_ttl` | `300` | 官方文本缓存 |
| `report_warm_enable` | `1` | 后台静默预热 `/战报` 快照 |
| `report_warm_interval` | `240` | 预热间隔（<60 夹到 60） |
| `api_watch_enable` / `api_watch_interval` | `1` / `60` | `/api` 监测 Issue #60，最低 60 秒 |
| `max_stale_seconds` | `3600` | 主源失败时本地快照的最长可用窗口 |
| `backup_json_url` | 空 | 同结构备用快照 |

### 6.7 其余段

- `paths`：对照表相对路径（`var_table` / `starmap` / `guide`），相对项目根解析。
- `webui`：`host` 固定 `127.0.0.1`（只绑本机），`port` 默认 `8630`。
- `inject`：WS 注入测试用的假成员号/昵称。
- `runtime`：`node` 可执行名（默认 `node`）、`draw_timeout_seconds`（画卡超时）、`btk_timeout_seconds`（BTK 桥接超时）。

### 6.8 环境变量

| 变量 | 作用 | 谁读 |
| --- | --- | --- |
| `HD2_PROJECT_DIR` | 项目根（含 `hd2_config.py` / `config.json` / `tables/`） | 插件、控制台、启动器 |
| `HD2_CONFIG` | 指定另一个配置文件，覆盖默认位置 | `hd2_config`、测试脚本 |
| `HD2_FONT` / `HD2_FONT_BOLD` | 指定图卡字体文件（Linux 无 CJK 字体时救急） | 渲染层 |

## 7. 接入官方 QQ 机器人

### 7.1 平台侧准备

1. 登录 [QQ 开放平台](https://q.qq.com/)，创建/选择机器人（群机器人）。
2. 在「开发 → 开发设置」取得 **AppID** 与 **AppSecret**（Secret 只显示一次，注意保管）。
3. 开通需要的权限：群聊消息（`GROUP_AT_MESSAGE_CREATE`）、图片/富媒体上传。部分能力需要提交审核或只能先在**沙箱环境/测试群**使用。
4. 把机器人**添加进目标群**（群主或管理员操作）。添加后，腾讯会为「该机器人 × 该群」分配一个 **群 OpenID**（32 位十六进制），它与 QQ 群号完全不同。

### 7.2 AstrBot 适配器配置

WebUI → 平台管理 → 新增平台：

**Websocket 模式（推荐，最省事）**

| 字段 | 值 |
| --- | --- |
| `id` | 自定义实例 ID，例如 `HD2_QQbot`（要与 `config.json` 的 `bot.platform_id` 一致） |
| `type` | `qq_official`（界面显示「QQ 官方机器人(Websocket, 推荐)」） |
| `enable` | `true` |
| `appid` | 开放平台 AppID |
| `secret` | 开放平台 AppSecret |
| `enable_group_c2c` | `true`（开启后订阅群消息；关闭则只收频道消息） |
| `enable_guild_direct_message` | 按需（频道私信） |
| `use_markdown` | 按需；本项目的卡片是图片、文字卡是纯文本，不依赖它 |

**Webhook 模式（需要公网回调）**

`type: qq_official_webhook`，字段：`appid`、`secret`、`use_markdown`、`is_sandbox`、`unified_webhook_mode`、`webhook_uuid`、`callback_server_host`（默认 `0.0.0.0`）、`port`（默认 `6196`）。在开放平台把回调地址指向你的公网域名；本地测试用反向代理或内网穿透。

保存后启动。日志出现以下内容即连上：

```
[QQOfficial] Websocket session starting
```

### 7.3 项目 config.json

```json
"bot": {
  "platform": "qq_official",
  "platform_id": "HD2_QQbot",
  "groups": ["D203335FE1B9E94A587681E38BC87BC3"]
}
```

- `groups` 里的 OpenID 必须是**字符串**（JSON 数字会丢精度/不匹配）。
- 不填 `groups` 时插件不拦，但 AstrBot 的访问控制仍会拦——见下一节。

### 7.4 框架白名单（最容易卡住的一步）

AstrBot **4.29.3 起**不再读取 `platform_whitelist.json`，只认 `cmd_config.json` 里的全局 `platform_settings.id_whitelist`：

- WebUI → 配置 → 访问控制 → 白名单 ID 列表；
- 把群 OpenID 加进去（数字群号对官方 QQ 无效）；
- 修改后保存/重启，管线才会重新初始化。

被拦时的日志特征：

```
Session ID HD2_QQbot:GroupMessage:D203335FE1B9E94A587681E38BC87BC3 is not in the session allowlist
```

**怎么拿到群 OpenID**：把机器人拉进群，在群里 @它发一句话，然后查日志里的 `Session ID <平台ID>:GroupMessage:<OpenID>`；或查 `temp/指令日志.jsonl` 的 `blocked` 记录。换 AppID 后 OpenID 会变，需要重新采集。

### 7.5 验证

1. 群里 **@机器人 `/帮助`** → 应回复指令列表。
2. `@机器人 /战报` → 应回一张战况图（图片上传受平台权限限制，失败会退回文字）。
3. 官方 QQ 的引用菜单：回复机器人发的菜单再发 `2` 即可选择；菜单标题里的 `〔菜单 XXXX〕` 只是回执标记，**不需要手动输入**。

### 7.6 能力边界与注意事项

- **唤醒**：官方 QQ 群默认只有 @ 机器人的消息会送到框架（`GROUP_AT_MESSAGE_CREATE`）。想让机器人收到普通消息，需要平台侧具备「接收所有消息」能力并通过审核。
- **主动推送**：官方对主动消息有严格配额；本项目的控制台群发只支持 OneBot 通道。定时/批量推送请用 SnowLuma 通道。
- **进群欢迎**：官方 QQ 不提供成员变动通知，`welcome` 插件只在 OneBot 通道生效。
- **图片**：走官方富媒体上传接口，比 OneBot 慢；超大图可能失败并退回文字。
- **`/api` 自动推送**：在调用过 `/api` 的会话内生效，仍是「机器人被动回复」路径，受平台限制。

## 8. 接入 SnowLuma（OneBot v11）

> SnowLuma 是独立的 OneBot v11 实现（TypeScript 互操作运行时，协议定义参考 LagrangeV2，实现思路参考 NapCatQQ）：自动注入 QQNT 进程、自带 WebUI 与 OneBot HTTP/WS，支持 Windows x64 与 Linux x64/arm64。旧配置里的 `napcat.*` 段已废弃，统一为 `snowluma.*`。

### 8.1 安装

1. 安装官方 **QQNT 9.9.x**（Windows），先登录一次确认可用。
2. 从 [SnowLuma Releases](https://github.com/SnowLuma/SnowLuma/releases) 下载 **Windows x64 完整发行包**（Full），解压到固定目录（例如 `C:\SnowLuma`）。Lite 版需要 Node.js 24+，功能也更少。
3. 确认目录里有 `launcher.bat`、`index.mjs` 等文件，把路径填入 `snowluma.dir`。

### 8.2 首次登录

1. 双击 `launcher.bat`（或用本项目「一键启动」自动拉起）。SnowLuma 会监视并注入 QQ 进程，QQ 先启后启都可以。
2. 从其控制台日志取**一次性临时密码**，打开 WebUI `http://127.0.0.1:5099` 登录。
3. 在**桌面 QQ 窗口**用手机 QQ 扫码登录机器人号（不是 SnowLuma 页面扫码）。

### 8.3 配置 OneBot 网络

SnowLuma WebUI → OneBot 网络配置：

| 项 | 值 |
| --- | --- |
| 反向 WS 客户端（wsClients） | `ws://127.0.0.1:6199/ws`（指向 AstrBot） |
| role | `Universal` |
| accessToken | 自己生成/留空；填了就要与 AstrBot 的 `ws_reverse_token` 一致 |
| `messageFormat` | `string`（CQ 码字符串；控制台推送依赖它） |
| `reportSelfMessage` | `false`（避免机器人自己的消息形成回环） |

### 8.4 AstrBot 侧

WebUI → 平台管理 → 新增平台 → **OneBot v11**：

| 字段 | 值 |
| --- | --- |
| `id` | 例如 `hd2_bot_private` |
| `type` | `aiocqhttp` |
| `enable` | `true` |
| `ws_reverse_host` | `0.0.0.0` |
| `ws_reverse_port` | `6199` |
| `ws_reverse_token` | 与 SnowLuma 的 accessToken 一致；都留空也可以 |

### 8.5 项目 config.json

```json
"bot": {
  "platform": "snowluma",
  "platform_id": "hd2_bot_private",
  "groups": [134324143],
  "default_group": 134324143
},
"snowluma": {
  "webui_url": "http://127.0.0.1:5099",
  "onebot_http": "http://127.0.0.1:3000",
  "access_token": "与 OneBot 配置一致的 token",
  "dir": "C:/SnowLuma",
  "qq_exe": "C:/Program Files/Tencent/QQNT/QQ.exe"
}
```

### 8.6 验证

1. AstrBot 日志出现 OneBot 客户端连接（`aiocqhttp` / `ws` 相关），或控制台「🔍 状态」显示 WS 已连接。
2. 群里 **@机器人 `/帮助`**（或私聊）→ 应回复指令列表；`bot.allow_chat=false` 时非指令消息不会进 LLM。
3. 控制台「📤 一键群发」→ 战报，能真实发到 `default_group`。

### 8.7 常见坑

| 现象 | 原因 / 处理 |
| --- | --- |
| QQ 启动后没被注入 | QQ 版本不被支持；换 SnowLuma 支持的 QQNT 版本，或以管理员身份运行 launcher |
| WebUI 打不开 | 端口 5099 被占用，或 SnowLuma 没起来；看 launcher 窗口日志 |
| 送不到 AstrBot | 反向 WS 地址/端口写错，或 AstrBot 的 `ws_reverse_port` 不是 6199 |
| 401/反复重连 | accessToken 与 AstrBot 的 `ws_reverse_token` 不一致 |
| 控制台推送报 CQ 解析错误 | `messageFormat` 不是 `string` |
| 机器人自己回复自己 | `reportSelfMessage` 没关 |

### 9.2 安装 AstrBot（三选一）

**Docker（推荐，无桌面服务器）**

```bash
docker run -itd \
  -p 6185:6185 -p 6199:6199 \
  -e TZ=Asia/Shanghai \
  -v "$HOME/astrbot/data:/AstrBot/data" \
  --name astrbot \
  soulter/astrbot:latest
```

- `6185` = WebUI、`6199` = 反向 WS（SnowLuma 连入），两个都要映射；
- `-v` 左侧是宿主机目录，右侧固定 `/AstrBot/data`：**容器内所有数据（含 `cmd_config.json`、插件）都在这里**，不挂出来重装容器就全丢；
- Windows 下把 `"$HOME/astrbot/data"` 换成 `"%cd%\data"`（PowerShell 用 `${PWD}\data`）；
- 国内网络拉不到镜像时换成 `m.daocloud.io/docker.io/soulter/astrbot:latest`。

容器里装插件：`docker exec -it astrbot bash` → 进 AstrBot 的插件目录放置，或用 WebUI 的市场安装。

**pip / venv**

```bash
python3 -m venv ~/astrbot-venv
~/astrbot-venv/bin/pip install -U astrbot
~/astrbot-venv/bin/astrbot init     # 首次初始化（按官方 CLI 提示）
~/astrbot-venv/bin/astrbot run
```

**源码**：按官方仓库说明 `pip install -r requirements.txt` 后启动 `main.py`。

### 9.3 SnowLuma（Docker，无桌面扫码）

```bash
docker run -d \
  --name snowluma \
  --restart unless-stopped \
  --shm-size=1g \
  --ulimit nofile=65536:1048576 \
  --cap-add=SYS_PTRACE \
  --security-opt seccomp=unconfined \
  -e SNOWLUMA_WEBUI_HOST=0.0.0.0 \
  -e SNOWLUMA_WEBUI_PORT=5099 \
  -e SNOWLUMA_QQ_FLAGS="--disable-gpu --disable-software-rasterizer --disable-gpu-compositing" \
  -p 6081:6081 -p 5099:5099 -p 3000:3000 -p 3001:3001 \
  -v qq-gateway-data:/app/data \
  -v qq-client-config:/app/.config \
  -v qq-client-data:/app/.local/share \
  motricseven7/snowluma:latest
```

- `--cap-add=SYS_PTRACE` 与 `--security-opt seccomp=unconfined` **不能省**：SnowLuma 用 ptrace 把 hook 注入 QQ 进程，默认 seccomp 会拦。
- `--shm-size=1g` 给 QQ（Chromium）用，默认 `/dev/shm` 太小会崩。
- 只映射了 6081（noVNC 远程桌面）；WebUI 5099 与 OneBot 3000/3001 按需暴露，**不要裸放到公网**。
- 远程桌面密码：`VNC_PASSWD` 不填时首次启动随机生成，只在日志打印一次：

  ```bash
  docker logs snowluma 2>&1 | grep -E "远程桌面密码|remote desktop password"
  ```

- WebUI 临时密码同样只在首启日志出现一次：

  ```bash
  docker logs snowluma 2>&1 | grep -E "临时密码|initial credentials"
  ```

- 扫码：浏览器打开 `http://<服务器IP>:6081/`（noVNC），输入上面的远程桌面密码，在远程桌面里用手机 QQ 扫码。
- OneBot 配置：`http://<服务器IP>:5099/` → 反向 WS 填 `ws://<AstrBot地址>:6199/ws`。AstrBot 也在 Docker 里时，两者要放到同一网络，或用 `--network host` / `host.docker.internal`。
- 不用 Docker 也可下载 Linux 发行包，`./launcher.sh` 启动（需要桌面或 Xvfb 才能显示扫码窗口）。

### 9.4 项目部署

```bash
git clone https://github.com/Jerry114514/HD2-Bot-Release.git ~/HD2-Bot
```

## 10. AstrBot 收尾配置

1. **LLM Provider**：WebUI → 服务提供商 → 新增（DeepSeek / OpenAI 兼容等）→ 设为默认。`/分析`、普通聊天需要；其余指令不依赖 LLM。
2. **人格**：把 `persona/super-earth-persona.md` 全文粘贴到 AstrBot 的人格设定（或作为系统提示），否则普通聊天没有真理部口吻。
3. **唤醒**：`cmd_config.json` 的 `wake_prefix` 留空 = 仅 @ 唤醒；官方 QQ 群本来就只能 @。
4. **访问控制**：见 §7.4，4.29.3+ 只认 `platform_settings.id_whitelist`。
5. **插件开关**：12 个子系统可按需禁用（例如只用战报就禁用 btk/roll）；但 `guard` 与 `common` 是基础设施，`wiki` 与 `guard` 同时启用时引用候选菜单才生效。
6. **普通聊天**：`config.json` → `bot.allow_chat: true`，并确认已配置 Provider 与人格。

## 11. 启动器与 Web 控制台

### 11.1 一键启动

| 平台 | 入口 | 行为 |
| --- | --- | --- |
| Windows | `start.bat`（或用控制台「🚀 一键启动」） | 校验 `config.json` → 读 `astrbot.python` → `scripts/launch.py` |
| Linux | `./start.sh` | 同上，解释器不可用回退 `python3` |

`launch.py` 顺序：

1. AstrBot：6185 已在监听则跳过；否则用 `astrbot.exe` 启动并等待端口。
2. 协议端：`bot.platform` 为 OneBot 时启动 SnowLuma（`snowluma.dir` 下的 launcher），并提示扫码；官方 QQ 模式直接跳过。
3. Web 控制台：8630 未监听则后台拉起 `scripts/hd2_webui.py`（Windows 用 `pythonw`，Linux `start_new_session`）。
4. 打开浏览器 `http://127.0.0.1:8630`。

### 11.2 Web 控制台

```powershell
$env:HD2_PROJECT_DIR = "C:\HD2-Bot"
python scripts\hd2_webui.py
```

默认 `http://127.0.0.1:8630`，只绑定本机；变更请求校验 Host/Origin 与会话 token。功能卡片：

| 卡片 | 作用 |
| --- | --- |
| 🛠️ 一键启动部署 | 启动全部、打开协议端 WebUI、重启 SnowLuma / AstrBot / 控制台、查看状态 |
| 🚀 一键发送 | 向指定群真实发送 `/战报`、`/dss`、`/战线`、`/战役`、`/分析`、`/查表`、`/roll`、使用说明 |
| 📤 一键群发 | 向所有推送群群发战报/战线/战役/DSS/分析/使用说明 |
| 📊 / 🎲 / 🪐 / 🧬 / 📢 | 生成并推送战报、随机配装、星球信息、变种查询、自定义消息 |
| 👥 群号管理 | 维护 `bot.groups`（推送名单）；框架白名单请到 AstrBot WebUI 配置 |
| 🧪 查询推送 / 响应测试 | 免污染群的 WS 注入测试（回执仅为测试结果，不等于真实群接收） |
| 📋 指令执行流水 | 查看最近的指令事件与发送结果 |

> 控制台主动推送只支持 OneBot 通道（SnowLuma）；官方 QQ 通道会在入口处提示「请在 AstrBot 适配器中配置支持的会话能力」。

| 市场安装 | AstrBot 插件市场 → 更新（或卸载后重装）；更新后重载插件 |
| 仓库分散部署 | `git pull` → `python sync_plugins.py --target <plugins> --update` → 重载 12 个插件 |

更新前建议：停止插件/重启 AstrBot，避免运行中混用新旧核心。

### 13.2 备份

| 内容 | 位置 | 建议 |
| --- | --- | --- |
| 项目配置 | `<项目根>/config.json` | 每次改动后另存（控制台自动备份到 `temp/config_backups/`） |
| AstrBot 配置 | `~/.astrbot/data/cmd_config.json` | 改白名单/平台前备份 |
| 插件数据 | `~/.astrbot/data/plugin_data/astrbot_plugin_hd2_*` | 含 `mo_seen.json`、Wiki 名称缓存等 |
| 人格 | `persona/super-earth-persona.md` | 改后留副本 |

### 13.3 回滚

1. 插件：把 `.hd2-sync-backups/<uuid>/` 里的旧文件复制回插件目录，或 `git checkout <旧提交>` 后重新同步。
2. AstrBot：桌面版可用安装包/便携包覆盖回旧版本（便携壳不支持应用内更新）；Docker 用旧镜像 tag。
3. 配置：恢复 `cmd_config.json` 备份后重启，使管线重新初始化。

## 14. 故障排查

### 14.1 安装与启动

| 现象 | 排查 |
| --- | --- |
| 市场安装提示版本不兼容 | AstrBot < 4.29.3；升级后重试。「无视警告」过不了加载闸门 |
| 插件列表里只有 1 个套件，但回复重复 | 同时装了套件与 12 个分散插件；移走其中一套后重启 |
| `ModuleNotFoundError: astrbot_plugin_hd2_common` | 分散部署时 `HD2_PROJECT_DIR` 未设置，或只同步了部分插件；重新 `sync_plugins.py` |
| `config.json` 改了不生效 | 分散部署缺 `HD2_PROJECT_DIR`（退回默认值）；或改的是市场包外面的另一份 config |
| `/roll` 报「抽取暂不可用」 | 没装 Node ≥ 22，或 `runtime.node` 指向错误 |
| 图卡全部退回文字 | Pillow 缺失或字体异常；看日志里 PIL 报错 |
| `start.sh` 报 `\r` | 文件被转成 CRLF：`dos2unix start.sh` |

### 14.2 通道连接

| 现象 | 排查 |
| --- | --- |
| 官方 QQ 无响应，日志 `is not in the session allowlist` | 群 OpenID 没进 `id_whitelist`（§7.4） |
| 官方 QQ 完全连不上 | appid/secret 错误、机器人未启用、网络被限制；看 `[QQOfficial]` 日志 |
| OneBot 连不上 AstrBot | 反向 WS 地址/端口/token（§8.7） |
| 控制台显示 WS 未连接 | AstrBot 没监听 6199，或 SnowLuma 没启动 |
| 扫码报「账号已登录」 | 先退出该 QQ 号的其他 PC 客户端 |

### 14.3 指令与回复

| 现象 | 排查 |
| --- | --- |
| 群里完全不回话 | 1) AstrBot 白名单 2) 插件 `bot.groups` 3) `bot.platform` 与通道不匹配 4) 是否 @ 了机器人 |
| 只有官方 QQ 群不回 | `bot.platform` 仍是 `napcat` 时插件不拦官方群，但框架白名单会拦；以及 `platform_id` 是否写错 |
| 指令被当成聊天回复 | `bot.allow_chat` 已开且消息未命中指令；确认斜杠与指令名（`/帮助`） |
| 战报里星球名是英文 | 对照表未收录，属正常；可在 `tables/星图对照表_修正版.md` 补 |
| `/分析` 报错 | Provider 未配置或额度不足；`config.json` 不含密钥，配在 AstrBot |
| 引用菜单提示「无法确认」 | 4.29.2 及更早的已知差异；升级到 4.29.3+ 后重新查询 |

### 14.4 Linux

| 现象 | 排查 |
| --- | --- |
| 中文变方框 | 命中无 CJK 的字体：装 wqy/Noto，或 `HD2_FONT=/path/font.ttc` |
| 控制台显示「未监听」但服务在跑 | 服务绑定了 IPv6/其他地址；改绑 `0.0.0.0` 或 `127.0.0.1` |
| 重启 AstrBot 按钮无效 | `astrbot.exe` 必须指向真实可执行/包装脚本，且与运行中进程一致 |
| Docker 里 SnowLuma 起不来 | 缺 `SYS_PTRACE` / `seccomp=unconfined` / `shm-size=1g` |
| 无桌面无法扫码 | 用 6081 noVNC 打开远程桌面里的 QQ 扫码 |

### E. 从 NapCat 迁移

旧版部署（v1.0.0 及更早）用 NapCat 注入 QQ 并配置 `napcat.*`。当前版本：

1. `config.json` 的 `napcat` 段整体改名为 `snowluma`，字段对应：`webui_url`→`webui_url`、`token`→`access_token`、`dir`→`dir`。
2. `bot.platform` 可继续写 `napcat`（等价 OneBot 通道），也可改 `snowluma`。
3. 反向 WS 地址不变：`ws://127.0.0.1:6199/ws`，role `Universal`。
4. 不再需要 NapCat 的 `NapCatWinBootMain` 注入启动；SnowLuma 自带注入。

历史 NapCat 步骤可在仓库 Git 历史中查阅（本文件已按 SnowLuma/官方 QQ 双通道重写）。

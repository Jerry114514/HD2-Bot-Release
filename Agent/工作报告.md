# 工作报告（脱敏）

> 本项目全程基于 DeepSeek V4-Flash 的 Agent 能力生成。以下为开发全过程报告（隐私信息已脱敏：QQ 号/群号/token/API Key/本机路径均以占位符代替）。

## 一、项目背景与目标

基于 AstrBot + NapCat 构建《绝地潜兵 2》（Helldivers 2）QQ 群战况机器人，实现：
1. 战况速报（Major Order 重要指令、目标星球战况、战区玩家分布、最新资讯）
2. 星球信息查询（抵抗度、行动变量、POI 特殊状态）
3. 行动变量对照表查询（`/查表`）
4. DSS 状态、战役列表、LLM 战局分析
5. 随机战备（`/roll`）、变种扫描查询
6. Web 控制台（一键部署/推送/测试/自重启）

## 二、架构

```
┌─────────┐   OneBot v11 (WS)   ┌──────────┐
│  NapCat │ ◄─────────────────► │  AstrBot │  ← 6 个 HD2 插件
│ (QQ 接入)│    ws://:6199/ws    │ (框架)   │
└─────────┘                     └────┬─────┘
                                     │ 数据抓取
                          ┌──────────▼──────────┐
                          │ Helldivers Companion│ ← 战役/DSS/新闻/星球
                          │ + helldivers2.dev   │ ← 星球名映射
                          └─────────────────────┘
```

- AstrBot：QQ 群机器人框架（插件、LLM 接入、消息管线、平台白名单）
- NapCat：OneBot v11 实现（QQNT 注入），WS 客户端连 AstrBot 的 6199 反向 WS
- 插件：war_report / planet_info / lookup / roll / variant_query / guard
- Web 控制台：浏览器管理面板（一键启动部署、推送、WS 注入测试、自重启）

## 三、关键实现

### 1. 数据源
- 重要指令：`helldiverscompanion.com/live/assignments/recent.json`
- 实时数据（新闻/战役/DSS/星球状态）：`get-api-data-live`
- 星球名映射：`api.helldivers2.dev/api/v1/planets`（需 X-Super-Client/X-Super-Contact 头）
- 星球页面（行动变量/POI）：Playwright 渲染抓取

### 2. 翻译体系（三层）
- DeepSeek LLM 优先（术语表 LLM_GLOSSARY 注入，保证译名统一）
- 本地修正表（BRIEF_TRANSLATION_OVERRIDES / TERM_FIXES）
- MyMemory 机翻兜底
- 新闻按 id 缓存到 news_cache.json，新闻不变输出不变

### 3. 数据字段踩坑（重要）
- `campaign.race` 字段**不可靠**（全为 1），敌方阵营要从 `planetStatus.owner` 判断：1=超级地球 / 2=终结族 / 3=机器人 / 4=光能族
- `campaign.type`：0=解放战（进攻）、1=防御战
- DSS `spaceStations.tacticalActions` 是**全部候选**行动，实际生效的行动要从停靠星球页面的行动变量（OPERATIONAL PARAMETERS 区）抓取
- API 行动名可能是 `ORBITAL BLOCKADE`（词库是 ORBITAL BLOCK），需归一化
- 星球页面解析：raw_params 截取 3000 字符且截到 POINTS OF INTEREST 之前（防历史时间线误匹配）

### 4. 消息触发与过滤
- 所有指令 `/` 前缀触发（无需 @），guard 插件拦截非 / 消息（关闭 LLM 自由聊天）
- **必须过滤机器人自己发的消息**（`sender_id == self_id`），防止同号多端自我触发循环
- 平台级白名单：按平台实例区分群（default / napcat）

### 5. 测试体系
- **WS 注入测试**（napcat_ws_inject.py）：伪装 WS 客户端直连 AstrBot 6199 注入群消息事件，端到端验证机器人响应，不污染群聊
- 关键：NapCat `reportSelfMessage=false` → 主号自己发的消息不上报 AstrBot，推送无法测响应
- WS 握手必须带 `X-Client-Role: universal` + `X-Self-ID` 头（aiocqhttp 强制，否则 400）
- AstrBot 处理消息时会调 `get_group_member_info` 等 API，测试脚本必须回假响应

### 6. Web 控制台
- ThreadingHTTPServer（默认 8630），深色主题卡片式界面
- 功能：一键启动部署（AstrBot+NapCat+二维码+验证）、重启 NapCat / WebUI（独立进程自愈）、状态检查、一键发送、推送、注入测试并推送
- pythonw/python 最小化窗口运行，bat 一键启动

## 五、踩坑记录（给二次开发者的经验）

1. **Windows 路径大小写不敏感**：`hd2-bot` 与 `HD2-Bot` 是同一目录！归档/复制时注意不要原地操作运行目录
2. **AstrBot 会话历史污染**：旧人格的固定回复会存进 conversations 表，污染后续 LLM 上下文——改人格后仍出现旧回复，先清会话历史（content JSON 中文可能转义，需 json.loads 后搜索）
3. **PowerShell 管道破坏 UTF-8**：含中文输出/写文件必须用 Python 脚本或 -Encoding UTF8
4. **重启 AstrBot 勿全杀 python 进程**：`ProcessName -match python` 会误杀 Web 控制台；精确匹配 `launch_backend`
5. **hosts #S302 劫持**：GitHub/Google 域名被指到 127.0.0.1 时需走 ghproxy 镜像
6. **cron 定时推送**：必须用 agentTurn（isolated）+ 明确 prompt + timeoutSeconds；systemEvent 注入主会话不会执行脚本

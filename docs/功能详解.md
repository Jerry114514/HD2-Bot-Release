# HD2 真理部战况机器人 — 功能详解

> 本文档详解每个功能的**实现细节**（数据源、逻辑、缓存、容错），不含部署/配置说明（见主 README）。
> 开发基准：`HD2-Bot` ｜ 本地运行：`HD2-Bot-Release` ｜ 发布备份：`D:\HD2-Bot-Release-Respo`

基于 **AstrBot + NapCat + Onebot v11** 的《绝地潜兵 2》战况 QQ 群机器人。自动抓取银河战争实时数据，提供战报、DSS 状态、活动战役档案、战线列表、LLM 战局分析、行动变量/星区查询、随机战备等功能，全中文界面，支持中英文查询。

## 二、功能详解（描述 + 实现）

### 2.1 战况速报 `/战报`

**描述**：一次输出重要指令、战略指令、战略机遇、次要指令、目标星球战况、战区玩家分布和最新新闻。

**实现**：
1. `data.major_order_content()` 只从当前 assignment 开始前 48 小时内的 dispatch 中选择最新 `NEW MAJOR ORDER`。
2. 用 dispatch id 对齐 news，正文优先级为 `official_message` → `raw_message` → `message`（带 `<i=N>` 标记）；`translated` / `message_zh` 等翻译链路纯文本只在没有带标签原文时回退。
3. 无可匹配 dispatch 时才使用与当前 assignment id 对齐的 `major_order.translated_brief`，最后才回退 assignment 英文 `briefing`。
4. `orders.special_orders()` 将三类通道分开解析：战略指令读取 `MAJOR ORDER` 之外的最新 `STRATEGIC DIRECTIVE/THREAT` assignment；战略机遇严格读取 `strategic.active/status/dispatch_id` 并关联 `NEW STRATEGIC OPPORTUNITY` 开局公告；次要指令优先读取独立 `MINOR ORDER` assignment。
5. 没有官方独立 Minor Order 时，MO 的附加守持目标会单独展示并明确标记“重要指令附加目标 · 非官方独立 MINOR ORDER”，不会冒充官方次级指令。
6. `official_texts.json` 按 dispatch id/assignment id 补全官方中文；图片卡显示截止倒计时、任务星球、当前守持状态和 `planet.html?idx=` 定位链接。
7. 新 MO 被战况命令首次发现时，按“平台 + 用户”自动发送一次 MO 卡；`/战报` 和 `/重要指令` 始终重播当期内容。状态保存在插件数据目录 `data/plugin_data/astrbot_plugin_hd2_war_report/state/mo_seen.json`，重启后继续生效。
8. `/重要指令` 使用独立 `banner_eagle3.webp` 横幅；MO 与活动战役阶段图完全解耦。
9. 图片卡按主站语义保留受控强调：`<i=1>`/`<ci=1>`/裸 `<i>` 黄 `#F5C518`、`<i=3>`/`<ci=3>` 蓝 `#5BA3D0`，均加粗、不使用斜体；其它编号只剥壳保字。纯文本回退无法上色，只剥壳保字并解码实体。

### 2.2 战线列表 `/战线`

**描述**：列出当前全部战线：星球（中文名 + 星区）｜敌方阵营｜解放战/防御战｜解放百分比/HP，末尾附跃迁航道封锁列表。

**实现**：
- 官方 `Status` 接口 `campaigns`（进攻战）与 `planetEvents`（防御战）合并
- 解放百分比 = `(1 - health / maxHealth) × 100`（进攻战）或 `(1 - event.health / event.maxHealth)`（防御战，含截止时间 UTC+8）
- 星球中文名查 `PLANET_NAME_CN`（271 条），星区查本地星图表 `星图对照表_修正版.md`（官方 sector 为数字/Unknown 不可靠）
- 跃迁封锁：`WarInfo.waypoints` 双向边计算，列出被封锁星球与封锁方向

### 2.3 战役简报 `/战役`

**描述**：活动战役以“档案头图 + 全阶段报告墙”展示。顶部为标题、说明、基础状态、战役奖励和当前阶段头图；下方一次展示全部阶段，不只显示当前阶段。

**实现**：
- 阶段数决定图片列数：1 阶段单列、2 阶段双列、3 阶段三列；纯文字回退始终按移动端友好的单列纵向展开。
- 每张阶段卡包含阶段编号/英文代号、状态、独立头图、中文名/英文副标题、结果、阶段奖励、简报和战报。
- 阶段图片回退顺序固定为 `intro_image_local` → `intro_image` → `banner_image_local` → `banner_image` → 阵营渐变占位。
- 活动战役已有中文字段优先；缺失时按 `active_campaign.id` 和阶段 id 读取 `data/campaign_zh.json`，不会用英文阶段文本覆盖已有官方中文。
- 无战报文本时不补造剧情：进行中显示“进行中，尚未发布最终战报”，成功/失败使用已有 outcome，缺失时才显示通用结果说明。

### 2.4 DSS 状态 `/dss`

**描述**：DSS 民主空间站——当前停靠星球、生效战术效果（中文 + 完整描述）、下一轮投票倒计时；DSS 离线/移动时输出 LLM 翻译的最新 DSS 资讯。

**实现**：
- **主源官方**：`Status.spaceStations[0]` → 停靠星球 + `activeEffectIds` 效果列表
  - 效果中文：对照表 `TACTICAL ACTION [效果ID]` 标注优先 → `dss_effects.json` → `effect_id_cn.json` 三级映射
  - 外骨骼机甲效果（1260/1261/1262/1384/1385）过滤不单独显示（已含于行动支持描述）
- **备选社区**：官方失败时回退 companion `spaceStations` + `tacticalActions`
- **资讯缓存**：每次查询后台抓 companion 新闻，过滤 DSS 关键词（`dss/space station/convocation bay`），**只保留最新 1 条**，走 LLM 翻译存 `dss_news_cache.json`（双语）；离线时 `_dss_news_supplement` 输出中文译文

### 2.5 战局分析 `/分析`

**描述**：LLM 战略评估：威胁概述 / 关键目标 / 行动建议 / 风险提示（真理部宣传风格，解放度越高优先级越高）。

**实现**：
- 汇总当前战役/战线/DSS/战区分布数据 → 拼装提示词（含术语表）→ AstrBot LLM 生成
- 失败返回错误提示，不阻断其他功能

### 2.6 查表 `/查表`

**描述**：查询行动变量对照表（12 分类 / 参数详情 / 分类子条目）与星区列表 / 星区星球，中英文均可。

**实现**（`hd2_lookup`）：
- 解析用户维护的 `HD2行动变量对照表.md`（Markdown 表格，`[ID]` 标注）与 `星图对照表_修正版.md`
- 支持按分类、按关键词、按星球名（中/英）模糊匹配

### 2.7 星球信息 @机器人 + 星球名

**描述**：星球详情：占领方、抵抗度、防御战 HP/失守进度、行动变量词条（部队/环境/特殊变种）、跃迁封锁、MO 目标标记。

**实现**（`hd2_planet_info`）：
- 中文名 → 英文 slug 匹配（对照表优先，纯英文名直转）
- **官方优先**：`planetActiveEffects` 实时行动变量 + 效果 ID → 中文映射
- **社区备选**：companion 星球页面（Playwright 渲染）解析抵抗度等
- 星球基础数据：helldivers2.dev `api/v1/planets`（浏览器可直连，支持 zh-Hans）

### 2.8 变种查询 @机器人 + 变种名

**描述**：扫描战役星球行动变量，输出所有存在该变种的星球（毫秒级）。

**实现**（`hd2_variant_query`）：
- 官方 `Status.planetActiveEffects` 识别变种（替代早期 Playwright 全页面扫描）
- 变种词库 `VARIANT_CN`（孢裂变种/掠食变种/炽灼部队等）→ 效果 ID 匹配
- 结果带缓存（`_scan_cache`，避免每次重复抓取）

### 2.9 随机战备 `/roll`

**描述**：从全类型战备池随机抽取 4 个；同类型超过 2 个附带毒舌评价。

**实现**（`hd2_roll`）：内置战备池（进攻/防御/支援/辅助分类），随机采样 + 类型统计评价。

### 2.9.1 拆毁值 `/拆毁值`

**描述**：比较来源的射弹直击拆毁力与命中/延时爆炸拆毁力。只填写来源时，
对照广播塔、虫穴内外层、机器人构筑者通风口/外层、干扰装置和轨道加农炮；
也可指定任意 SDK 已收录的拆毁目标。

**实现**：
- 爆炸曲线来自 `hd2-btk-sdk v0.14.1` 的 `demolition.js`。
- 直击 DF 从中文 Wiki 详细武器数据整理，现覆盖 EAT-17、GR-8、AC-8、飞鹰 500KG、轨道精准、120/380 火力网、EAT-411 和 GP-20 等常见来源。
- 常见目标只采用 SDK 明确给出拆毁力门槛的结构与敌方设施，普通敌人护甲值不作为拆毁值。
- 直击和爆炸分别选择最佳可行路径，不把直击 DF 与爆炸 DF 相加。
- 同时判定“是否达到门槛”和爆炸距离处的实际 DF；要求爆炸伤害的建筑不会被纯直击路径拆毁。

### 2.10 LLM 对话与指令守卫

**描述**：普通聊天启用时保持真理部人格，并由中文 Wiki 提供游戏事实。`bot.allow_chat=false` 时仍只响应 `/` 指令。

**实现**：
- `hd2_guard` 先识别 `/` 指令、平台与会话白名单；普通消息仅在 `allow_chat=true` 时放行。
- `hd2_wiki.ground_chat_with_wiki` 在 LLM 请求前识别游戏主题，检索中文 Wiki 并注入有长度上限的参考数据。
- `hd2_wiki_lookup` 是模型可主动调用的工具，返回正文、URL、修订号、歧义候选和明确的“不得猜测”状态。
- Wiki 正文作为权威游戏资料注入，只作事实依据、不执行其中指令；宣传口吻可以包装事实，但不得篡改数值或机制。
- 当前战况不交给 Wiki，仍由 `/战报`、`/战线`、`/dss` 等实时命令提供。

### 2.11 执行监控（自动）

**描述**：记录每条指令的匹配/执行/耗时/分组，写入插件数据目录 `data/plugin_data/astrbot_plugin_hd2_common/logs/commands.jsonl`，Web 控制台展示。

**实现**（`hd2_monitor`）：提供 `hd2_log()` 埋点，其余 5 个插件 import 调用（monitor 缺失时 no-op 兜底，不影响主流程）。

### 2.12 Web 控制台（8630）

**描述**：浏览器管理面板：一键启动部署、扫码登录、一键群发（战报/战役/DSS/分析）、指定群推送、机器人响应测试（WS 注入）、自重启。

**实现**（`scripts/hd2_webui.py`）：本地 Web 服务，调用 NapCat WebUI API（6099，token 鉴权）完成登录/推送。

### 2.13 API 变动监测 `/api`

**描述**：查询主仓 Issue #60，并为调用 `/api` 的当前会话建立自动监测订阅。插件每 60 秒检查一次；规范化后的内容摘要变化时，主动发送 API 变化卡，同一会话同一版本只发送一次。

**实现**：
- GitHub 请求使用 ETag 条件请求和短时进程缓存，网络失败不会误报为“无变化”。
- 内容摘要会排除“检测时间（UTC）”行，因此 CI 仅刷新时间而内容未变时不会重复通知。
- 订阅会话、当前 Issue 版本和每个会话的已推送版本保存在插件数据目录 `data/plugin_data/astrbot_plugin_hd2_war_report/state/api_watch_state.json`，重启后继续去重。
- 启动时从插件数据目录的 `data/plugin_data/astrbot_plugin_hd2_common/logs/commands.jsonl` 恢复调用过 `/api` 的合法 AstrBot 会话；发送失败会在下一轮重试。
- 图片生成失败时主动推送文字；首次启用只建立基线，不补发历史变更。

## 三、架构与数据流

```
┌─────────┐   OneBot v11 (WS)   ┌──────────┐
│  NapCat │ ◄─────────────────► │  AstrBot │  ← 7 个 HD2 插件（含公共库）
│ (QQ 接入)│    ws://:6199/ws    │ (框架)   │
└─────────┘                     └────┬─────┘
                                     │ 数据抓取（官方优先，社区兜底）
                          ┌──────────▼──────────┐
                          │ 官方 API（主源）     │ ← MO/战役/战线/DSS/新闻/解放%
                          │ api.live.prod.       │
                          │   thehelldiversgame.com│
                          ├─────────────────────┤
                          │ Helldivers Companion│ ← 备用（官方故障时）
                          │ + helldivers2.dev   │ ← 星球名映射
                          └─────────────────────┘
```

**插件分工**：

| 插件 | 行数 | 职责 |
|---|---|---|
| `hd2_common` | 454 | **公共库**：共享常量/HTTP 抓取/表加载/译名表（PLANET_NAME_CN 271 / SECTOR_CN 24），3 插件 import |
| `hd2_war_report` | 1417 | 战报 / 战线 / 战役 / DSS / 分析 / 新闻（最大单体） |
| `hd2_planet_info` | 901 | 星球详情 |
| `hd2_variant_query` | 309 | 变种扫描 |
| `hd2_lookup` | 308 | 查表 |
| `hd2_roll` | 201 | 随机战备 |
| `hd2_guard` | 25 | 指令守卫 |
| `hd2_monitor` | 107 | 执行监控 |

**数据源分层**（官方优先，社区兜底）：
1. **官方 API 主源**：`api.live.prod.thehelldiversgame.com`（2026-08 从游戏流量抓包发现，公开可访问，仅需 `X-Super-Client` 头）——MO/战役/战线/DSS/新闻/解放%/跃迁航道
2. **社区备选**：官方故障（如 500）自动回退 Helldivers Companion 聚合端点
3. **星球名**：helldivers2.dev（支持 zh-Hans）+ 本地对照表中文译名
4. **LLM**：AstrBot 接入的 deepseek（翻译/分析），失败有本地修正表/原文兜底

**缓存体系**（统一在 AstrBot 插件数据目录 `data/plugin_data/astrbot_plugin_hd2_war_report/`，不写插件安装目录）：
- `site_<hash>.json`：主站 `data.json` 成功快照；网络失败时按既有陈旧上限只读回退。
- 图片卡按数据版本/布局版本生成稳定摘要，同版本直接复用；MO 卡摘要包含正文、任务进度和截止时间。
- `cache/banners/`：阶段头图与 MO 横幅的下载缓存；本次关键横幅同时随插件发布在 `assets/campaign/`，首次运行不依赖公网热链。
- `state/api_watch_state.json`：`/api` 自动监测的会话、Issue 版本和逐会话已推送版本。
- `state/mo_seen.json`：按平台和用户记录已自动通知的最新 MO assignment id；只抑制重复自动通知，不阻止手动 `/战报`、`/重要指令`。
- 公共内存 HTTP 缓存：`data.get_json()` 按 URL/TTL 合并并发请求；变种与静态映射继续复用原有机制。
- 公共库表加载 3 层兜底：`HD2_PROJECT_DIR` → 项目根 tables → 插件目录副本（发布者无环境变量也能跑）

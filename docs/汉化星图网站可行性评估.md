# 汉化星图网站 + 部署 GitHub Pages 可行性评估

日期：2026-08-15
评估人：LobsterAI（HD2 战报机器人维护）

---

## 1. 目标

1. 汉化 helldiverscompanion.com 星图网站（中文界面 + 中文数据）
2. 部署到 GitHub Pages（免费静态托管）

## 2. 关键限制实测（2026-08-15 浏览器 CORS 实测）

| 数据源 | 浏览器直连 | 说明 |
|---|---|---|
| companion 聚合（get-api-data-live） | ❌ CORS 阻止 | 无 Access-Control-Allow-Origin，前端无法直连 |
| 官方 API（api.live.prod.thehelldiversgame.com） | ❌ CORS 阻止 | 自定义头触发 preflight 被拒 |
| helldivers2.dev（planets 等） | ✅ 可直连 | 实测 200 可读，甚至支持 Accept-Language: zh-Hans |

**核心结论：纯静态站点无法在浏览器直接调 companion/官方 API，必须绕开 CORS。**

## 3. 方案对比

### 方案 A：Fork companion 源码汉化 + GitHub Pages
- 流程：fork CarlosSant47/helldivers2-companion（SvelteKit）→ 汉化前端字符串 → adapter-static 构建 → 部署 Pages
- 问题：
  1. 工程量大（5MB+ JS 主包，字符串散落各处，更新频繁需持续跟进）
  2. **数据 CORS 问题依旧**：前端仍需调 companion/官方 API（被挡）→ 除非自建后端/代理
  3. 许可合规（companion 大概率 AGPL-3.0，修改版需开源）
- 可行性：低-中

### 方案 B：自建轻量中文星图站 + 构建期数据抓取（推荐 ⭐）
- 数据基础已具备（本机器人现有资产）：
  - 官方 API 直连（Python 已验证，X-Super-Client 头）
  - 星图对照表（269+ 译名）、行动变量对照表、效果映射表（dss_effects/effect_id_cn）、LLM 术语表
- 架构：
  1. **构建脚本**（Python）：官方 API + companion 聚合 → 生成静态 JSON（星球/战役/MO/DSS/新闻，中文译名替换）
  2. **静态前端**（HTML/JS）：星图/列表/详情页，读本地 JSON
  3. **GitHub Actions 定时重建**（每 5-15 分钟）：刷新数据 → 部署 Pages
- 优点：
  1. 纯静态，GitHub Pages 完美支持
  2. 不依赖 companion 源码（无许可问题）
  3. 中文质量可控（对照表/术语表完全自主）
  4. 数据延迟 = 重建间隔（分钟级，可接受）
- 缺点：非实时（需定时重建）；星图可视化（SVG 星系图）需自行实现（可参考 companion 布局）
- 可行性：**高**

### 方案 C：Cloudflare Workers 代理 + 实时前端
- Workers 转发官方/companion API + 注入 CORS 头 → 前端实时数据
- 优点：实时性好
- 缺点：需 Cloudflare 账号；Workers 免费额度（10 万请求/天，够用）；前端仍需自建
- 可行性：高（可作为 B 的增强）

## 4. GitHub Pages 部署要点

1. GitHub Pages 免费静态托管（公开 repo）✓
2. 本机 GitHub 被墙——但部署可用 GitHub Actions（云端执行，不受本机网络影响）；或用户手动 push
3. 需要 GitHub 账号 + 公开仓库
4. 自定义域名可选

## 5. 推荐实施路径

1. **首选方案 B**：构建期数据抓取 + 静态前端 + Actions 定时部署
   - 阶段 1：数据层（Python 抓取脚本，产出中文 JSON）——复用现有官方 API + 对照表
   - 阶段 2：前端（HTML/CSS/JS 静态页：星球列表/详情/战役/DSS/新闻）
   - 阶段 3：GitHub Actions（定时重建 + pages deploy）
2. 后续可加方案 C（Workers 实时代理）作为实时数据通道

## 6. 风险

1. 官方 API 稳定性（时好时坏，如 2026-08-15 全天 500）——构建脚本需多源兜底（官方 + companion + hd2dev）
2. 星图可视化工作量（星系图/跃迁航线）——建议 V1 先做列表/详情，V2 加星图
3. GitHub 网络：本机 push 需代理或依赖 Actions

## 结论

**汉化 + GitHub Pages 可行**，推荐「自建静态站 + 构建期数据抓取」（方案 B）。数据基础已具备（官方 API 直连 + 全套中文对照表），核心工作是前端页面 + 构建脚本 + Actions 流水线。

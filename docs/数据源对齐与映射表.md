## 3. 翻译链路（去 LLM 化）

| 内容 | 权威中文位置 | 机器人行为 |
|---|---|---|
| MO 简报 | `data.json.major_order.translated_brief`（翻译仓库官方 zh-Hans 采集） | 直接使用；站点缺失才回退 LLM，再回退 MyMemory |
| 新闻 | `data.json.news[].translated`；回退 `data/translated/TransNews.json` | 直接使用并播种进本地缓存（site 来源优先级最高）；站点没有的条目才 LLM |
| 战役简报/阶段/奖励名 | `data.json.active_campaign.*_cn`；回退 `/api/Episode/{war}/` | 站点中文直接使用；缺失才回退 `zh-Hans` 官方 Episode，仍缺才 LLM |
| 战略机遇状态 | `data.json.strategic.status_cn` | 直接使用 |
| DSS 资讯 | `data.json.news[]`（DSS 相关条目已带官方中文） | 不再单独走 LLM 翻译缓存；仅站点完全缺失时保留旧 LLM 逻辑 |
| 术语表 | `tables/hd2_variables.json`、`galactic_effects.json`、`术语表.txt` | 已同步主站版本 |

**结论：日常路径（站点可达）全部零 LLM、零 MyMemory。**

## 4. 缓存与失效

| 缓存 | 位置 | TTL | 版本判定 | 失效策略 |
|---|---|---|---|---|
| data.json | 内存 + `cache/site_doc_cache.json` | 120s（`data.news_cache_ttl`） | `fetchedAt` 作为 `ver` 存入缓存 | 过期后台刷新，前台先用缓存；上游变化立即换版本 |
| 实测帧 | 内存 + `cache/recent_frames_cache.json` | 300s | `index.generatedAt`；**生成时间 >3 小时视为断更，整块停用实测**（与主站 rate-source.js 同口径） | 断更自动回退推演，绝不让旧帧冒充实测 |
| 星球表 | 内存 + `cache/planet_table_cache.json` | 3600s | 缓存内 `ver`=站点 `fetchedAt` | 同上 |
| 站点表文件（tables/） | 仓库内置 + `cache/tables_cache/` 远程副本 | 24h | 文件级 mtime | 本地缺失时从 Pages 拉取一次 |
| MO 缓存 / 新闻缓存 / DSS 资讯缓存 | `cache/*.json` | 按 NMO 新闻窗口判定 | 新闻 id + `translated_at` 版本 + 内容指纹 | 站点译文（site 来源）永远可覆盖 LLM 译文；LLM 永不覆盖 site |

## 5. 缺失字段与空数组的约定

- 所有访问走 `hd2_datasource` 的安全取值（类型检查 + 缺省 None）。
- **“数据缺失”显示“暂无/数据不足”，“真实数值 0” 显示 “0.0”**——实测速率返回 `None`（帧不足/满血顶格/易主）与 `0.0`（真实停滞）是两个不同结果，格式化层必须区分。
- 主站字段缺失、数组为空、单一来源超时均不抛出到用户界面，按回退链降级并在日志记录。

## 6. 迁移说明（部署者视角）

1. 旧 `config.json` 无需任何修改即可启动：新增配置全部有默认值（见 `config.example.json` 的 `data.*` 段）。
2. 可选覆盖项：`data.site_base`（主站基址）、`data.recent_base`（实测帧基址）、`data.transnews_url`、`data.campaign_zh_url`、`data.tables_base`、`data.official_api_url`、`data.super_client`（官方 API 风控头，建议填自己的 QQ 号）、`data.recent_fresh_max_hours`。
3. `data.news_source` 保留旧语义：`hd2map`（默认，站点优先）/ `api`（只走实时 API）。
4. `plugins/*/cache/` 目录可整体删除，重启后自动重建（旧缓存没有版本号会被视为“无版本”并按 TTL 自然过期）。
